# SKS Maximo Utils Web UI（待开发）

## 背景

目前导入能力只有 CLI 和 JS API：

- CLI：`sks-maximo import-xxx <fileName> [env]`
- JS：`importMaxObject`、`importMaxPresentation`、`importMaxDomain`、`importMaxAutokey`、`importMaxScript`、`importMaxAppInfo`、`importMaxAppInfoV1`、`importMaxIntObject`、`batchImport`

缺少一个可视化界面：可以选择导入类型、选择本地目录、批量执行，并像
[maxmessage/index.vue](../../../maximo-manager-panel/src/views/maximo_v2/maxmessage/index.vue)
的导入弹窗那样，直观看到成功/失败统计和逐条返回信息。

## 目标

新增 Web UI，提供：

1. 选择导入类型；
2. 选择本地目录（或目录下的文件）；
3. 批量导入并展示进度；
4. 导入结束后展示成功/失败统计和明细，风格参考 `maxmessage` 页面；
5. 支持查看/复制接口返回的原始 JSON；
6. 支持“计划导入”编排：把多个导入任务排成有序列表，一键顺序执行（参考 VSCode 插件的“计划导出”）。

## 现有接口与返回格式

| 导入类型 | JS 方法 | 接口 |
|----------|---------|------|
| 对象配置 | `importMaxObject` | `/api/script/SKS_IMP_MAXOBJECT` |
| 应用信息（新） | `importMaxAppInfo` | `/api/script/SKS.AUTOSCRIPT.SCREENS?_action=importAppInfo` |
| 应用信息（旧） | `importMaxAppInfoV1` | `/api/script/SKS_IMP_MAXAPPINFO` |
| 应用 XML | `importMaxPresentation` | `/api/script/SKS.AUTOSCRIPT.SCREENS` |
| 域配置 | `importMaxDomain` | `/api/script/SKS_IMP_MAXDOMAIN` |
| AutoKey | `importMaxAutoKey` | `/api/script/SKS_DEPLOY_AUTOKEY` |
| 自动化脚本 | `importMaxScript` | `/api/script/SKS_IMP_MAXSCRIPT` |
| 对象结构 | `importMaxIntObject` | `SKS.AUTOSCRIPT.OBJECTS` |

`importMaxAppInfo` 使用 JS 调用时直接返回接口响应对象，结构示例：

```json
{
  "app": "SKS_APP",
  "_apiAction": "imp",
  "status": "success",
  "data": {
    "maxapps": [ { "status": "success", "operation": "update", "sks:successSumTotal": 1 } ],
    "presentation": []
  },
  "sks:successSumTotal": 1,
  "sks:failSumTotal": 0
}
```

其余导入方法返回 `true` / `false`，批量导入由 `batchImport` 汇总为：

```json
{
  "total": 10,
  "success": 8,
  "failed": 2,
  "failedFiles": ["a.json", "b.json"],
  "startTime": "...",
  "endTime": "...",
  "duration": 1234
}
```

## 功能需求

### 1. 导入类型选择

下拉框，选项与上表一致；每个类型绑定：

- 需要的文件扩展名（`.json` / `.xml`）；
- 对应的导入方法；
- 是否支持目录批量导入。

默认选中“对象配置”。

### 2. 本地目录选择

UI 由 `sks-maximo -web` 启动的本地服务承载，目录选择推荐走后端：

- 方案 A（推荐）：页面提供路径输入框 + “选择目录”按钮，后端调用 Windows 目录选择框（PowerShell FolderBrowserDialog / Electron dialog），返回绝对路径；
- 方案 B：页面使用 `<input webkitdirectory>`，只能拿到浏览器内的文件列表，拿不到绝对路径，也无法配合后端的按路径扫描。

首期采用方案 A，同时保留“手动输入/粘贴绝对路径”作为兜底。

### 3. 导入参数

- 环境（`envs` 中的 key，如 `prod`、`prod_en`）；
- 并发数（默认 1，串行）；
- 日志名称前缀（可选）；
- 是否递归子目录；
- 扩展名过滤（按导入类型自动带出，可修改）。

### 4. 执行与进度

- 开始 / 停止按钮；
- 进度条：`已完成 / 总数`；
- 当前文件、成功数、失败数实时刷新；
- 停止后保留已完成结果，未执行文件标记为“已取消”。

### 5. 结果展示（参考 maxmessage）

导入完成后：

- 顶部标签：`导入成功` / `导入失败`（存在失败即失败）；
- 统计文案：`共 N 个文件：成功 X，失败 Y，耗时 Z ms`；
- 明细表格列：
  - 文件 / 引用（`sks:ref`）
  - 状态（`success` / `failed`）
  - 操作（`added` / `updated` / `deleted`）
  - 消息（接口返回的失败原因）
  - 耗时
- “查看详细返回信息”弹窗：
  - Tab 1：列表（虚拟滚动，支持大数据量）；
  - Tab 2：原始 JSON（只读，可复制）；
- 失败文件支持“一键重试”。

对于只返回 `true/false` 的导入方法，明细只展示文件级状态；
对 `importMaxAppInfo` 则解析 `data` 中的行级结果，按行展示。

### 6. 配置

沿用 `~/.sks/nodeutils/config.json`：

- 环境下拉从 `envs` 动态生成；
- 显示当前 `baseUrl`，避免误操作到错误环境；
- `langcode` 由所选环境决定，英文环境（如 `prod_en`）导入时自动带 `_langcode=EN`（接口参数使用大写）。

## 导入编排（参考 VSCode 插件的“计划导出”）

参考 [maximo-script-vscode-plugin/webview-ui/src/App.tsx](file:///E:/gitwork/maximo-script-vscode-plugin/webview-ui/src/App.tsx) 中 `scheduledExportPlan` 的实现方式：任务列表 + 启停 + 总进度 + 单任务进度 + 执行日志。这里平移为“计划导入”。

### 编排模型

```json
{
  "name": "hd 环境应用信息导入",
  "env": "hd",
  "concurrency": 1,
  "tasks": [
    {
      "id": 1,
      "importType": "appinfo",
      "sourceType": "directory",
      "path": "C:/Temp/tohd/maxappxml_backup_20261103_161741_ZH",
      "extFilter": ".json",
      "recursive": true,
      "logname": "应用信息",
      "options": { "dmDeploySet": false },
      "enabled": true
    }
  ]
}
```

- 每个任务一行，可选择导入类型、目录/文件、扩展名、是否递归、日志名，以及该类型的专属参数（如应用信息的 `dmDeploySet`、`errorAssert`）；
- 支持启用/禁用、删除、上移/下移调整执行顺序；
- 提供“添加任务”“保存计划”“加载计划”“开始执行”“停止”；
- 任务按列表顺序串行执行；单个任务内部复用 `batchImport`，按 `concurrency` 并发；
- 进度分两级：总进度（已完成任务数/总任务数）+ 当前任务进度（已完成文件数/总文件数）；
- 执行日志实时输出；
- 任务结束后汇总每个任务的成功/失败数与耗时，点击任务可查看文件级/行级明细。

### 计划持久化

- 全局：`~/.sks/nodeutils/import-plan.json`
- 项目级（可选）：当前目录 `.sks-import-plan.json`
- 页面支持导入/导出计划 JSON，便于在不同机器间复用。

## 技术方案

### 启动方式

```bash
sks-maximo -web -e hd
```

- `-web` / `--web`：启动本地 Web 服务并打开浏览器；
- `-e` / `--env`：指定默认环境（页面内仍可切换）；
- CLI 参数解析需要支持 `-web`，与普通导入命令互斥；检测到 `-web` 时不执行导入命令，直接进入 Web 模式；
- 默认监听 `127.0.0.1`，端口可通过 `--port` 指定，避免暴露到外网。

### 后端

新增本地轻量服务，直接复用 `nodeutils` 中的导入方法：

| 接口 | 说明 |
|------|------|
| `GET /api/envs` | 返回配置中的环境列表及 `baseUrl` |
| `POST /api/scan` | 按目录/扩展名/递归参数扫描文件 |
| `POST /api/run` | 执行单个任务或整个计划，SSE 推送进度与日志 |
| `POST /api/stop` | 停止当前计划，保留已完成结果 |
| `GET/POST /api/plan` | 读取/保存编排计划 |

### 前端

- 使用 Vue 编写（建议 Vue 3 + Vite + Element Plus）；
- 若要求与 `maxmessage` 视觉完全一致，可改用 Vue 2 + Element UI；
- 页面由三部分组成：
  1. 编排区：任务列表、添加/删除/排序、计划保存/加载；
  2. 执行区：开始/停止、总进度、当前任务进度、实时日志；
  3. 结果区：任务汇总 + 文件级/行级明细 + 原始 JSON（参考 `maxmessage`）。

## 验收标准

1. 可通过 `sks-maximo -web -e hd` 启动并打开页面，默认环境为 `hd`；
2. 可添加多个导入任务，选择类型/目录/扩展名/递归/参数，并支持启停、排序、删除；
3. 计划可保存、加载、导入导出 JSON；
4. 执行计划时任务按顺序串行，总进度与当前任务进度实时更新，可停止；
5. 单个任务失败不阻断后续任务，结果中明确标记；
6. 结束后展示每个任务的成功/失败数量、耗时与失败文件列表；
7. 明细表格可查看文件级/行级状态与消息，原始 JSON 可复制；
8. 失败项可重试；
9. 请求使用所选环境的 `baseUrl`，`importMaxAppInfo` 的 `_action=importAppInfo` 与 `_langcode` 正确；
10. CLI 与 JS API 行为不受影响。
